# First Principles Thinking Engine

A framework and future app for breaking problems down to their most fundamental parts, then building better solutions from the ground up.

## Why

First principles thinking is one of the most powerful ways to solve hard problems. Instead of copying existing solutions, blindly following assumptions, or reasoning from analogy, it forces you to ask what is actually true at the most basic level.

Very few people consistently think this way. But when someone does, it can be life-changing. It makes them harder to fool, better at solving new problems, and much more capable of building original solutions.

The core belief behind this project: if you can learn to reason from first principles, you can attack almost any problem more clearly.

## What Is First Principles Thinking?

First principles thinking means reducing a problem to its fundamental, irreducible components.

Instead of asking:

> How do people usually solve this?

You ask:

> What do we know is true? What assumptions are we making? What are the basic parts of this problem? If we rebuilt the solution from scratch, what would we do?

The point is not to sound philosophical. The point is to remove inherited assumptions and expose the real structure of the problem.

## Framework

Use this process:

1. Define the problem clearly.
2. List the assumptions inside the problem.
3. Separate facts from beliefs, guesses, habits, and inherited defaults.
4. Break the problem into fundamental components.
5. Ask which components are truly necessary.
6. Rebuild the solution from the components that remain.
7. Compare the rebuilt solution against existing approaches.
8. Test the solution against reality and update the model.

## Example Pattern

For any problem, ask:

- What exactly am I trying to solve?
- What do I believe is true here?
- Which of those beliefs are actually proven?
- What are the smallest parts of this problem?
- What constraints are real, and what constraints are assumed?
- If no existing solution existed, how would I build this from scratch?
- What solution becomes obvious after removing false assumptions?

## App Idea

Build an app that performs first principles thinking with the user.

The user gives the app a problem. The app then:

- Clarifies the problem.
- Identifies hidden assumptions.
- Breaks the problem into fundamental components.
- Separates facts, constraints, unknowns, and guesses.
- Challenges weak assumptions.
- Rebuilds possible solutions from the ground up.
- Shows the reasoning path clearly.
- Helps the user compare original thinking against conventional solutions.

The goal is not just to answer the user. The goal is to teach the user how to think better while solving the problem.

## What It Does

- Turns vague problems into structured problem statements.
- Breaks large problems into irreducible parts.
- Exposes assumptions that may be limiting the solution.
- Helps users reason from reality instead of habit.
- Creates solution paths that are grounded in fundamentals.
- Makes first principles thinking easier to practice repeatedly.
- Helps people learn the framework by using it, not just reading about it.

## MVP Questions

- What kinds of problems should the first version support: personal, technical, startup, research, product, or life decisions?
- How can the app identify assumptions without becoming annoying or overly philosophical?
- How should it distinguish facts, constraints, guesses, and inherited beliefs?
- What is the right format for the final output: breakdown, decision tree, solution plan, or reasoning map?
- How can the app teach first principles thinking while still giving a useful answer?
- How can the system avoid pretending that uncertain assumptions are facts?
- Can users compare a conventional answer with a first-principles rebuilt answer?
- How should progress be measured: better decisions, better solutions, or better thinking habits?

## First Version

Start with a simple problem breakdown tool. The user enters a problem, and the app returns:

- A clarified problem statement
- Key assumptions
- Known facts
- Unknowns
- Fundamental components
- Rebuilt solution paths
- Next experiments or actions

The first version should make the user feel the difference between ordinary problem-solving and first principles thinking.
